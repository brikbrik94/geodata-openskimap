# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`geodata-openskimap` is a data pipeline ("plugin") that downloads OpenSkiMap's
GeoPackage, converts it to PMTiles, and packages it with a MapLibre style and
sprite set for a larger deployment system. It is one of a family of sibling
`geodata-*` plugin repos (e.g. `geodata-overlays`) that all conform to the
shared spec in `geodata-plugin-standard/GEODATA_PLUGIN_STANDARD.md` (git
submodule) — read that file before changing
directory layout, `dist/manifest.json` shape, or logging conventions, since
those are load-bearing for the external deployment/monitoring system, not
just local convention.

Before acting on the repo-specific guidance below, also read
`oe5ith-coding-rules/AGENT_INSTRUCTIONS.md` (git submodule) in full — its
mandates (scope discipline, TODO vs. ROADMAP, versioning/changelog, proposal
cycle for rule changes) are binding and are not repeated here.

Most prose docs (`README.md`, `GEMINI.md`, `docs/*.md`) are written in
German; bash/Python identifiers and code comments are in English. Match
whichever convention the file you're editing already uses.

## Commands

```bash
./setup.sh                         # first-time setup: creates data/src, work,
                                    # logs, dist/{pmtiles,styles,assets/sprites},
                                    # checks system tools, creates .venv
bash scripts/check_dependencies.sh # verify aria2c, ogr2ogr, tippecanoe are installed
./update.sh                        # smart orchestrator: only builds if upstream data changed
./run.sh                           # force a full pipeline run regardless of upstream changes
```

There is no test suite, linter, or package manager in this repo (no
`package.json`/`requirements.txt`); `scripts/ci/utils.py` and
`generate_manifest.py` use only the Python standard library.

To run/debug a single stage instead of the full `run.sh`:

```bash
bash scripts/download.sh              # aria2c conditional-get of the .gpkg into data/src/
bash scripts/convert.sh               # ogr2ogr extract + tippecanoe build into work/
python3 scripts/generate_manifest.py  # copy work/ + styles/ + assets/ into dist/, write manifest.json + layer-list.json
```

## Pipeline architecture

Three entry points per the plugin standard's "Dreifaltigkeit" (§1):

- **`setup.sh`** — one-time initialization (directory structure, `.venv`,
  dependency check).
- **`update.sh`** — the script to schedule (e.g. via cron): runs pre-flight +
  `scripts/download.sh`, then compares the downloaded GeoPackage's mtime
  against `data/.last_build_source_mtime` (written by `run.sh` after its last
  *successful* build, not just after any download) to decide whether new
  data actually arrived. Only then does it invoke `run.sh` — this makes a
  failed/interrupted build retryable on the next `update.sh` run instead of
  being masked as "unchanged".
- **`run.sh`** — unconditional full build, four phases, each a separate
  script, each expected to `set -euo pipefail` and abort the whole run on
  failure:
  1. **Pre-flight** — `scripts/check_dependencies.sh` verifies `aria2c`,
     `ogr2ogr` (GDAL), and `tippecanoe` are on `PATH`.
  2. **Ingest** — `scripts/download.sh` fetches the GeoPackage URL defined in
     `sources/openskimap.env` into `data/src/` via `aria2c --conditional-get`
     (skips the download if unchanged since last run). Skipped when `run.sh`
     is invoked by `update.sh` with `GEODATA_SKIP_DOWNLOAD=1` (data already
     fresh from the change-detection step).
  3. **Processing** — `scripts/convert.sh`:
     - `ogr2ogr` extracts five layers from the GeoPackage into `work/*.jsonseq`
       (GeoJSONSeq): `ski_areas_point`, `ski_areas_multipolygon`,
       `lifts_linestring`, `runs_multipolygon`, `runs_linestring`.
     - `tippecanoe` builds `work/openskimap.pmtiles` from those layers with
       `-L <name>:<file>` (preserves exact layer names), zoom 0–14,
       `--drop-densest-as-needed --extend-zooms-if-still-dropping`.
     - Intermediate `.jsonseq` files are deleted after the tippecanoe run.
  4. **Finalize** — `scripts/generate_manifest.py` copies `work/openskimap.pmtiles`,
     `styles/openskimap-style.json`, and `assets/sprites/openskimap/*` into the
     matching `dist/` subfolders, writes `dist/manifest.json` (schema below),
     and (via `generate_layer_list.py`) `dist/layer-list.json` (plugin
     standard §5 — this repo's dataset is an overlay, so the legend-metadata
     file applies).

`dist/`, `work/`, `data/`, and `logs/` are build output / scratch space —
all gitignored and regenerated by the pipeline, not hand-edited.

Both `run.sh` and `update.sh` write JSONL run-logs via
`scripts/ci/run_logger.sh` (plugin standard §7) to
`${GEODATA_LOG_DIR:-/var/log}/geodata_openskimap_{update,build}_{history.jsonl,status.json}`;
best-effort, never aborts the run on a logging write failure.

Any script change should keep the same phase boundaries and the
fail-fast/abort-on-error behavior, since sibling plugin repos and the
external orchestrator assume `update.sh`/`run.sh` exit non-zero on any stage
failure.

### manifest.json schema

Produced by `generate_manifest.py`, consumed by the external deployment
system per `geodata-plugin-standard/GEODATA_PLUGIN_STANDARD.md` §4:

```json
{
  "version": "1.0",
  "project": "geodata-openskimap",
  "generated_at": "<UTC ISO8601>",
  "datasets": [
    {
      "id": "openskimap", "type": "overlay", "source": "openskimap",
      "sprite_id": "openskimap", "name": "OpenSkiMap",
      "style_path": "styles/openskimap-style.json",
      "pmtiles_path": "pmtiles/openskimap.pmtiles"
    }
  ],
  "resources": {
    "sprites": [{ "id": "openskimap", "path": "assets/sprites/openskimap" }],
    "fonts": []
  }
}
```

### Style / sprites

`styles/openskimap-style.json` is a MapLibre style referencing a single
`pmtiles://{TILES_BASE_URL}/openskimap.pmtiles` vector source
(`ski_source`) and a `{TILES_BASE_URL}`-relative sprite URL — the
`{TILES_BASE_URL}` placeholder is filled in by the external deployment
system, not by this repo. Layers are named `ski-areas`, `ski-runs-*`
(alpine/nordic/sled/connection variants, casing + fill + label layers), and
`ski-lifts-*`, each pointing at one of the five `source-layer`s produced by
`convert.sh`. Sprite source images/JSON live in
`assets/sprites/openskimap/` (`sprite[.@2x].json/.png`) and are copied
verbatim into `dist/` by the finalize phase — edit the source files, never
the `dist/` copies.

## Logging convention ("Corporate Identity")

Every script sources `scripts/ci/utils.sh` (bash) or imports from
`scripts/ci/utils.py` (Python) for standardized colored console output —
documented in `docs/corporate-identity.md`. Use these instead of raw
`echo`/`print` in any pipeline script:

- `log_header "..."` — major phase banner
- `log_step N total "..."` — numbered step within a phase
- `log_info` / `log_success` / `log_warn` / `log_error` — status lines

`scripts/ci/utils.sh` also has `get_rel_path <full> <root>` for printing
paths relative to `PROJECT_ROOT` in log output.

`scripts/ci/run_logger.sh` provides the separate JSONL run-log API
(`run_log_init`/`run_log_str`/`run_log_num`/`run_log_raw`, plugin standard
§7.4) used by `run.sh`/`update.sh` — unrelated to the console logging above,
sourced in addition to `utils.sh`, not instead of it.
